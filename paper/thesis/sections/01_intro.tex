\begin{abstract}
    \textbf{このdraftで相談したいこと}\par\smallskip
    複数のプログラムが連携するシステムで不具合が起きたとき，「どの部分から調べるとよいか」を，観測データから絞り込む研究です．
    普段の動きを時系列モデルで予測し，予測からのずれの分布を比べる方法を考えています．

    \medskip
    今回は完成した本文ではなく，論文の組み立てを示します．
    「解きたい問題が伝わるか」「方法と実験が問いに対応しているか」「統計的な説明に無理がないか」を見ていただきたいです．
    各節の箇条書きは，これから何を書くかのメモです．

    \medskip
    \noindent\textbf{構成：} 序論で問題と問いを示し，背景・関連研究で準備した後，提案手法→評価実験→考察→結論と進みます．
\end{abstract}

\section{序論}
\label{sec:intro}

\subsection{どんな問題を解きたいのか}
\begin{itemize}
    \item 通販サイトの「商品検索」「在庫確認」「決済」のように，役割を分けて動く小さなプログラムをサービスと呼ぶ．こうしたサービスを連携させた仕組みがマイクロサービスシステムである，と具体例から説明する．
    \item 在庫確認が遅くなると，それを待つ決済も遅くなることがある．したがって，「遅く見える場所」と「不具合の出発点」は同じとは限らない．この例を簡単な図で示す．
    \item こうした不具合の原因を調べることを，障害原因分析（RCA: Root Cause Analysis）と呼ぶ．本研究では，原因と思われるサービスを順位付きで示し，調査を助けたい．
\end{itemize}

\subsection{何を手掛かりにするのか}
\begin{itemize}
    \item 各サービスには，CPU使用率や応答にかかる時間などの時系列データがある．「正常に動き続けていたら，どんな値になったか」を予測し，実際の値との差を手掛かりにする．
    \item 扱うのは，不具合が起きたこととその開始時刻が分かっている状況．不具合の有無を検知する段階ではなく，起きた後に原因候補を絞る段階を対象にする．
    \item 大きな変化が出たサービスが必ず原因とは限らない．提案する順位が実際に調査の役に立つかは，原因の分かっているデータで確かめる．
\end{itemize}

\subsection{論文で答えたい三つの問い}
\label{sec:rq}
\begin{itemize}
    \item \textbf{問い1：} 提案する方法は，既存の方法と比べて，原因サービスをどの程度上位に挙げられるか．
    \item \textbf{問い2：} 時系列を予測することと，ベイズ的に分布変化を比べることは，それぞれ何に役立つか．
    \item \textbf{問い3：} どんな条件でうまくいき，どこに限界があるか．設定や測定単位が変わっても結果は安定するか．
\end{itemize}

\subsection{この研究で示したいこと}
\label{sec:claims}
方法の提案に加えて，どの工夫が役立ったか，どこに限界があるかまで実験で確かめたい．
この三点を，提案手法→評価実験→考察・結論の順に説明する．
