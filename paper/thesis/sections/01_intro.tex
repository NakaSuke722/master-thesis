\section{序論}
\label{sec:intro}

\subsection{どんな問題を解きたいのか}
\begin{itemize}
    \item 通販サイトの「商品検索」「在庫確認」「決済」のように，役割を分けて動く小さなプログラムをマイクロサービスと呼ぶ．こうしたサービスを連携させた仕組みがマイクロサービスシステムである，と具体例から説明する．
    \item たとえば在庫確認が遅くなると，それを待つ決済も遅くなることがある．したがって，「遅く見える場所」と「不具合の出発点」は同じとは限らない．この例を簡単な図で示す．
    \item こうした不具合の原因を調べることを，障害原因分析（RCA: Root Cause Analysis）と呼ぶ．本研究では，原因と思われるサービスを順位付きで示し，調査を助けたい．
\end{itemize}

\subsection{何を手掛かりにするのか}
\begin{itemize}
    \item 各サービスには，CPU使用率や応答時間など，メトリクスと呼ばれる時系列データがある．「もし正常に動き続けていたら，どんな値になったか」を予測し，実際の値との差を手掛かりにする．
    \item 扱うのは，不具合が起きたという事実とその開始時刻が分かっている状況．不具合の有無を検知する段階ではなく，起きた後に原因候補を絞る段階を対象にする．
    \item 大きな変化が出たサービスが必ず原因とは限らない．提案する順位が実際に調査の役に立つかは，原因の分かっているデータで確かめる．
\end{itemize}

\subsection{リサーチクエスチョン（RQ）}
\label{sec:rq}
\begin{itemize}
    \item \textbf{RQ1：} 提案する方法は，既存の方法と比べて，原因サービスをどの程度上位に挙げられるか．
    \item \textbf{RQ2：} 時系列を予測することと，ベイズ的に分布変化を比べることは，それぞれどの程度，そして何に役立つか．
    \item \textbf{RQ3：} どんな条件でうまくいき，どこに限界があるか．設定や測定単位が変わっても結果は安定するか．
\end{itemize}

\subsection{本研究の貢献}
\label{sec:claims}
方法の提案に加えて，どの工夫が役立ったか，どこに限界があるかまで実験で確かめたい．
この三点を，提案手法→評価実験→考察・結論の順に説明する．
