\section{評価実験}
\label{sec:experiment}

\subsection{どんなデータで，何を正解として調べるか}
\begin{itemize}
    \item RCAEvalは，障害原因分析の方法を比較するためのオープンデータセット．システムに意図的な不具合を起こし，各サービスのメトリクス時系列と，原因サービス・開始時刻を記録している．
    そのうち三つのシステム（Online Boutique, Sock Shop, Train Ticket）における5種類の障害注入パターン（CPU, MEM, DELAY, LOSS, DISK），計375件の障害事例を使う．\\
    \href{https://github.com/phamquiluan/RCAEval}{https://github.com/phamquiluan/RCAEval}
    \item 障害前後からそれぞれ最大600時点を取り出す．正解は不具合を起こしたサービスとし，どの方法にも同じ障害事例を与える．データ版などの再現に必要な情報は，後の稿で条件表へまとめる．
    \item 注意：使える開始時刻や学習に使う区間なども比較条件である．既存方法を今回のデータに合わせて変更した部分は，後で明記する．
\end{itemize}


\subsection{RQ1：既存手法との比較}
\begin{itemize}
    \item 提案手法と既存方法について，AC$@k, \:k=1,3,5$とAvg$@k\:k=5$の二つの指標で評価する．
    \item RCA手法が出力する根本原因メトリクスランキングの出力結果から，「上位1つ・3つ・5つに正解が入った割合」を計算する．この上位$k$件の正解率をAC@$k$と呼ぶ．
    \item 主な評価指標にはAvg@5を用いる．これは，正解サービスを上位5候補の中でどれだけ高く順位付けできたかを評価する指標である．正解が1位なら1，2位なら0.8，3位なら0.6，4位なら0.4，5位なら0.2，上位5候補に入らなければ0とし，全375件の障害事例で平均する．AC$@k$もAvg$@k$も0から1の値をとり，1に近いほど正解率が高い．
    \item 表案：方法ごとの正解率を，3つのデータセット別で示す．計算にかかる時間は，仮想環境を使うなどして測定条件をそろえる．
\end{itemize}

\subsection{RQ2：アブレーションによる各要素の評価}
手法には，複数の構成要素が組み合わさっている．各要素ごとの有効性を調べるため，提案手法の一部を除いたり置き換えたりした場合の性能を比較する．これをアブレーションという．
\begin{itemize}
    \item 時系列予測を使わず観測値の分布を直接比べる場合，障害後も実測値を使って予測する場合，予測の不確かさを補正しない場合を，提案方法と比較する．
    \item ベイズ的な比較の役割は，BFの代わりに一般化尤度比検定(GLRT)を使う比較を調べる．変えた要素と固定した条件を表にし，複数の変更による差を一つの工夫の効果としない．
\end{itemize}

\subsection{RQ3：感度分析と適用上の限界}
\begin{itemize}
    \item AR次数などのハイパーパラメータ設定や，秒からミリ秒への単位変換によって順位が変わるかを調べる．不具合の種類ごとの得意・不得意も見る．
    \item 正常時のデータを前半・後半に分け，後半を仮の「障害後」として得点を計算する．不具合がなくても高得点になるなら，その得点を障害の確かな証拠と読めるかを考える．
    \item 注意：同じデータを何度も見て設定を選んでいる点を明記する．小さな精度差を最適性の証明とせず，統計的な不確かさも併記する．
\end{itemize}
