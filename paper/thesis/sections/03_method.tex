\section{提案手法}
\label{sec:method}
\noindent AMBERは，本研究で提案する原因候補の順位付け手法の名前．
「正常時を予測する→予測からのずれを比べる→調査候補を並べる」の順に説明する．

\subsection{正常に動き続けた場合を予測する}
\begin{itemize}
    \item 観測項目ごとに正常時のデータからARモデルを作り，障害後の期間へ予測を延ばす．尺度が違う項目を扱えるよう，正常時の値を基準に標準化する．
    \item 障害後の実測値を次の予測へ使うと，不具合による変化まで「いつもの動き」として追いかけてしまう可能性がある．そこで，障害後はモデル自身の予測値を使って先へ進める．
    \item 図案：同じ時系列に二通りの予測を重ね，「実測値を追いかける予測」と「正常時のモデルを継続した予測」の違いを見せる．後者も仮定に基づく予測であり，不具合がなかった世界を正確に復元したとは言わない．
\end{itemize}

\subsection{遠い先ほど予測が不確かになることを考慮する}
\begin{itemize}
    \item 実測値と予測値の差を予測誤差とする．正常時の一時点先誤差と，障害後の多時点先誤差をそのまま比べてよいか，という問題を説明する．
    \item ARモデルから予測距離ごとの誤差分散を求め，差の大きさを補正する．予測の不確かさだけで得点が高くなるのを抑える，という狙いを伝える．
    \item 注意：予測が発散しないための係数の制約も必要．また，分散を補正しても誤差同士が独立になるとは限らず，係数の推定誤差も残る．詳しい式は次の稿で整理する．
\end{itemize}

\subsection{予測誤差の分布変化を得点にする}
\label{sec:method-bf}
\begin{itemize}
    \item 補正した予測誤差を正規分布で近似し，$H_0$「正常時と障害後で平均・分散が共通」と，$H_1$「それぞれ別の平均・分散を持つ」を比べる．
    \item 平均・分散を積分したBFの対数を観測項目の得点にする．ここで，事前分布の選び方と，どの量を推定・積分しているのかを説明する．AR係数自体は点推定である．
    \item 確認したい点：時点間の依存が残る誤差に，この分布比較を使う説明は十分か．仮定と近似を明記し，得点を原因の確率とは呼ばない．
\end{itemize}

\subsection{観測項目の得点をサービスの順位へまとめる}
\begin{itemize}
    \item サービスごとに得点が高い観測項目を最大三つ選び，その平均をサービスの得点とする．それを高い順に並べ，調査候補として返す．
    \item 図案：複数の観測項目の得点→サービスごとの得点→候補順位，という小さな例を作る．この平均は分布変化をまとめるためのルールであり，サービス全体のBFではない．

\end{itemize}
