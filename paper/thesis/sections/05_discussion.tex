\section{考察}
\label{sec:discussion}

\subsection{どこでうまくいき，どこで失敗したか}
\begin{itemize}
    \item RQ1--RQ3に対応させて，精度，各要素の役割，条件による違いを整理する．表の読み上げで終わらず，「この結果はどう説明できるか」へ進む．
    \item 成功例と失敗例を一つずつ取り上げ，観測時系列・予測・得点・順位を並べる．不具合の影響を予測が吸収した，という説明が実例と整合するかを見る．
    \item 注意：予測誤差の変化と順位の変化が対応していても，それだけで原因と結果の関係を証明したとはしない．例の選び方も説明する．
\end{itemize}

\subsection{高い得点をどこまで信用してよいか}
\begin{itemize}
    \item これまでの正常時データの確認でも，高い得点が出ることがあった．「障害が起きた後の候補を並べる能力」と「得点から障害の有無を判断する能力」は別だと説明する．
    \item 正常時にも動きが変わること，正規性や独立性の近似，推定に使ったデータの再利用などを検討する．高得点の理由を一つに決めつけない．
    \item 相談したい点：この近似の下でBFを順位付けに使うことを，どこまで妥当と説明できるか．何を示せば，主張をもう一段強くできるか．
\end{itemize}

\subsection{うまくいかなかった案から何を学んだか}
\begin{itemize}
    \item 予測誤差の分布ではなく，AR係数や雑音分散そのものの変化をベイズ的に比較する案も試した．正常時の変動と障害を十分に区別できず，今回は採用していない．
    \item 数値積分が収束していても，仮説がデータに合い，原因をうまく順位付けできるとは限らない．この点を短く述べ，細かな試行履歴は本文の中心にしない．
\end{itemize}

\subsection{今回の結果だけでは言えないこと}
\begin{itemize}
    \item 少数のシステムと人工的な不具合での評価なので，別のシステムや実際の運用でも同じ精度が出るとは限らない．同じデータで設定を選んだ影響も残る．
    \item 障害の開始時刻を見つけること，サービス間の因果関係を明らかにすること，各候補に正確な原因確率を付けることは，今回の成果として主張しない．
    \item 統計的な仮定の問題と，評価データ・実験条件の問題を分けて書く．研究室には，見落としている制約がないかも確認してもらいたい．
\end{itemize}
